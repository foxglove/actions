Required provider model calls, party authentication/assessment traffic, Linear ticket delivery, private GCS evidence writes and GitHub Actions service traffic are operational service requests, not optional telemetry newly instrumented by Attack Runner. The service providers can retain their own access/audit/usage records under their service policies; Strix opt-out does not erase or control those records. These paths still need explicit destinations, credentials and payload handling. Local Strix usage/cost accounting and guarded run evidence remain necessary to enforce the $100/60-minute contract; they are not an outbound metrics feed. Dependency/source fetches and a pinned Strix sandbox-image pull are build or supply-chain traffic to perform in a controlled setup step, record and separate from scan runtime; no auto-upgrade belongs inside a run.

## Verification oracle for the implementation reviewer

Run an offline startup/shutdown/finding/error matrix at the exact Strix commit and resolved dependency lock in a capture environment with fake model and target endpoints. Launch through the actual TypeScript runner into its selected Python `run_strix_scan` bridge, set `STRIX_TELEMETRY=0`, `STRIX_NO_UPDATE_CHECK=1`, `OPENAI_AGENTS_DISABLE_TRACING=1` **before** importing Strix in that child, and pass an explicit environment allowlist. Assert the bridge process and sandbox attempt no DNS, TCP, HTTP or HTTPS connection to PostHog, Scarf, `app.strix.ai`, GitHub/PyPI update endpoints, OpenAI trace intake, Exa/Perplexity, or any OTEL/analytics endpoint. Verify intended model and target requests still work in the test harness, and inspect local logs/reports for credential and target redaction before private persistence. Include an inherited-variable negative case with `TRACELOOP_*`, `OTEL_*`, `LANGFUSE_*`, `LANGCHAIN_*`, `SENTRY_*`, Exa and Perplexity keys set in the parent: the child must strip them. A blocked attempted beacon is a test failure, since the user requested no metrics emitted to Strix; a firewall denial alone does not prove the application disabled emission.

Record exact source commit, dependency versions, command, environment variable **names** (never secret values), capture boundary, observed destination set, expected deny set, and exit results. Source inspection establishes the candidate controls; it does not prove zero egress from transitive dependencies, Docker runtime, hosted Actions infrastructure or a future Strix release.
